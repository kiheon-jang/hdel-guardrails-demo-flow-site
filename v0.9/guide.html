AI로 만든 변경에
이유와 이해를 남기는 플러그인

AI 코딩 도구에 설치해서 씁니다. 이 가이드는 Claude Code 를 예로 들고, Gemini CLI 용 확장도 같은 내용으로 있습니다. 기록은 AI가 써 주고, 사람은 "내가 이해했는지"만 직접 답합니다. 개발 부서와 비개발 부서가 같은 방법으로 씁니다.

1무엇인가요

AI 코딩 도구(예: Claude Code)에 명령 다섯 개를 더해 주는 플러그인입니다. 이름은 hdel ai-coding 이고, 명령은 모두 /ai-coding: 로 시작합니다. 평소에는 그중 하나만 씁니다.

PC마다 한 번설치

명령 두 줄

→
프로젝트마다 한 번/ai-coding:시작하기

규칙 문서를 넣음

→
작업할 때마다 ↻AI에게 요청 → /ai-coding:올리기

말로 시키고, 끝나면 올리기 하나만 입력

2왜 쓰나요

AI가 코드를 빨리 만들어 주지만, 그대로 반영하면 세 가지가 남지 않습니다.

이런 일이 생깁니다누가 왜 바꿨는지 모릅니다
이 플러그인을 쓰면변경마다 이유 · 바뀐 점 · 위험도가 기록으로 자동 작성됩니다.
이런 일이 생깁니다이해하지 못한 채 반영됩니다
이 플러그인을 쓰면올리기 전에 "어떻게 확인했나"를 내 말로 답해야 합니다. AI가 대신 채우지 못합니다.
이런 일이 생깁니다담당이 바뀌면 처음부터 봅니다
이 플러그인을 쓰면인수인계 문서가 변경마다 갱신돼, 새 담당이 바로 읽습니다.

올릴 때마다 세 가지가 남습니다: 반영 요청(PR) 본문 · 변경 기록 1건 · 갱신된 인수인계 문서.

3설치 — PC마다 한 번

이미 설치돼 있을 수 있습니다. 먼저 ①로 확인하고, 안 돼 있을 때만 ②와 ③을 합니다.

① 먼저 확인 · 10초이미 설치됐나요?

Claude Code 대화창에 /ai-coding:메뉴 를 입력합니다.

버튼이 나오면 설치된 것입니다. ②와 ③은 건너뛰고 4번으로 갑니다.

② PC 준비 · 지원 담당과 함께세 가지가 있어야 합니다
Claude Code프로그램이 열리면 됩니다
GitHub 로그인터미널에 gh auth status → "Logged in" 이 보이면 됩니다
Node.js터미널에 node -v → v18 이상 숫자가 나오면 됩니다

하나라도 안 되면 지원 담당에게 요청합니다. 설치에서 어려운 부분은 여기뿐입니다.

③ 설치 · 붙여 넣기 한 번아래 두 줄을 한꺼번에 복사해 터미널에 붙여 넣고 Enter
claude plugin marketplace add <저장소 주소> claude plugin install ai-coding@hdel

<저장소 주소> 자리는 개발 리더가 알려 준 주소로 바꿉니다. "Successfully installed" 가 나오면 끝입니다. Claude Code 를 닫았다가 다시 열고 ①을 한 번 더 확인합니다.

새 버전 받기: claude plugin marketplace update hdel 다음에 claude plugin update ai-coding@hdel

4프로젝트에 적용 — 프로젝트마다 한 번

프로젝트 폴더에서 Claude Code 를 열고 한 번만 합니다. 팀에서 누가 이미 했으면 건너뜁니다.

1

/ai-coding:시작하기 를 입력하고 세 가지를 고릅니다

카드 한 장에서 질문 세 개에 차례로 답합니다. 그러면 규칙 문서와 기록 양식이 프로젝트에 들어갑니다.

할 일: 세 가지 고르기 → 요약을 보고 [반영 (추천)] 누르기.

조직이 중요합니다. 개발 부서는 올릴 때 3문항, 비개발 부서는 1문항을 묻게 됩니다.

새 프로젝트
이미 운영 중
② 조직
개발 부서
비개발 부서

5평소 사용 — 올리기

AI에게 말로 시키고, 작업이 끝나면 /ai-coding:올리기 를 입력합니다. 그다음은 화면이 묻는 대로 따라 합니다. 주황색 테두리가 내가 누르거나 쓰는 곳입니다.

1

대화창에 /ai-coding:올리기 를 입력합니다

AI가 바꾼 내용을 모으고 시험을 돌립니다. 잠시 기다립니다.

할 일: 입력하고 Enter. 그다음은 기다리기.
/ai-coding:올리기
올릴 변경을 모으고 있습니다…
2

"작업 공간을 만들까요?" → [지금 하기]

내 작업을 따로 담아 둘 자리(브랜치)를 만드는 것입니다. 작업 내용은 사라지지 않습니다.

할 일: [지금 하기 (추천)] 누르기.

이미 작업 공간에서 일하고 있으면 이 질문은 나오지 않습니다.

작업 공간(브랜치)을 만들어 옮길까요?
지금 하기 (추천)
직접 할게요
3

이해 확인 → 내 말로 답합니다

이것만은 AI가 대신 써 주지 않습니다. 직접 해 본 것과 아는 것을 한두 줄로 씁니다.

비개발 부서 · 1문항어떻게 확인했나
개발 부서 · 3문항어떻게 동작하나 · 우려되는 점 · 왜 이 방식인가
할 일: 직접 입력 칸에 쓰기. 예) "화면에서 abc 를 넣어 보니 새 안내 글이 나왔고, 올바른 번호를 넣으면 전처럼 나왔어요"

거부되는 답: "확인함"처럼 너무 짧은 답, AI의 설명을 그대로 옮긴 답. 무엇이 바뀌었는지 모르겠으면 [전체 설명]을 눌러 먼저 읽습니다.

어떻게 확인했나 — 자기 말로 답해 주세요
이 질문 관련 설명 설명을 다시 봅니다
전체 설명
직접 입력 ← 여기에 씁니다화면에서 abc 를 넣어 보니…
4

요약을 보고 → [올리고 반영]

AI가 정리한 요약이 나오고, 카드 한 장에서 두 가지를 차례로 묻습니다. 다음 사람이 알아야 할 주의할 점이 없으면 [없음], 그리고 [올리고 반영]을 누릅니다.

할 일: [없음] 누르고, [올리고 반영 (추천)] 누르기.

요약이 내가 한 일과 다르면 [고칠 곳 있음]을 누르고 무엇이 다른지 씁니다.

올릴 내용 요약입니다. 제목 · 바뀐 점 3줄 · 내가 쓴 답

없음
이해 확인 답으로 충분
직접 입력 있으면 씁니다
② 이대로 올리고 반영할까요?
올리고 반영 (추천)
고칠 곳 있음
지금은 안 올림
5

허락을 묻는 창이 뜨면 → [허용]

팀 저장소에 올리기 직전에, 컴퓨터가 "이 명령을 실행해도 될까요?"라고 한 번 묻습니다. 사람이 마지막으로 확인하는 자리입니다.

할 일: [허용] 누르기.
이 명령을 실행할까요?
hdel pr create … --merge
허용거부
6

"반영됐습니다"가 나오면 끝

변경과 기록이 팀 저장소에 들어갔습니다. 누가 왜 바꿨는지, 내가 어떻게 확인했는지가 함께 남습니다.

할 일: 없음. 다음 작업은 새 대화에서 시작합니다.
반영 요청(PR) #12 가 반영됐습니다.
다음 작업은 새 대화에서 시작하면 토큰이 덜 듭니다.

6가끔 쓰는 것

명령은 모두 /ai-coding: 로 시작합니다. 명령만 치면 버튼이 나오니 뒤에 붙는 말은 외우지 않아도 됩니다.

이럴 때입력그러면
AI가 뭘 바꿨는지 모르겠다/ai-coding:파악하기 → [내 작업]바뀐 내용을 쉬운 말로 설명합니다. 올리기 전에 읽어 두면 이해 확인이 쉬워집니다.
처음 맡은 프로젝트를 알고 싶다/ai-coding:파악하기 → [프로젝트 전체] · [흐름도]인수인계 요약과 최근 변경 기록, 구조 그림을 보여 줍니다.
구조 문서와 흐름도를 만들고 싶다/ai-coding:분석하기코드를 읽어 문서를 만듭니다. 시간이 걸리고 토큰이 많이 드는 선택 기능입니다. 주로 개발자가 씁니다.
급해서 먼저 반영해야 한다/ai-coding:메뉴 → [긴급 올리기]먼저 반영하고, 이해 확인은 바로 뒤에 받습니다.
뭘 쳐야 할지 모르겠다/ai-coding:메뉴할 수 있는 일이 버튼으로 나오고, 상황에 맞는 것을 추천합니다.

7막혔을 때

화면에 나오는 말이렇게 합니다
답이 너무 짧습니다 / 설명을 그대로 옮긴 답은 거부됩니다이해 확인으로 돌아가 내가 직접 해 본 것을 내 말로 다시 씁니다.
코드에서는 ○○인데 답은 △△입니다. 맞나요?AI가 내 답과 실제 동작이 다르다고 본 것입니다. 맞으면 [그대로 둠], 헷갈리면 [이 질문 관련 설명]을 읽고 다시 씁니다.
로그인이 필요합니다본인 계정이라 직접 해야 합니다. 방법을 모르면 지원 담당에게 요청합니다.
처음 설정(시작하기)이 필요합니다이 프로젝트에 아직 적용하지 않은 것입니다. 위 4번을 합니다.
겹친 수정(충돌)이 있습니다 · 그 밖에 모르는 말더 누르지 말고 화면을 그대로 두고 담당 개발자나 지원 담당에게 보여 줍니다.
